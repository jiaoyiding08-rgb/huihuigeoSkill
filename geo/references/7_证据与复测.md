# 证据与复测

目录：证据层级、最小旁注、兼容与补采、脚本使用、测量口径、实验与首次检出。

## 证据层级

| 要回答的事 | 需要的证据 | 不能替代它的东西 |
|---|---|---|
| 公开页面可读 | 公开 URL、查看时间及正文快照 | 已点提交、保存草稿、后台成功状态 |
| 爬虫来过 | 有身份校验的访问记录 | 任意 User-Agent、浏览器能打开 |
| 搜索服务已收录 | 该服务的可复核索引检查 | 爬虫访问、Sitemap 提交 |
| 我方来源进入参考列表 | 完整参考面板、条目及来源身份 | 页面所有外链 |
| 正文引用我方来源 | 回答段、引用标记、来源 URL 的明确关系 | 参考列表出现、措辞相似 |
| 品牌提及或推荐 | 完整回答中的品牌原句、推荐语义与位置 | 来源标题或链接里出现品牌 |
| 推荐句有我方引用支持 | 推荐句对应我方来源，原文支持该句事实 | 品牌与引用分别出现在答案不同位置 |
| 硬事实正确 | 逐条主张、核实事实和对应版本 | 听起来合理、文章检查通过 |

每层分别填 `yes`、`not_observed` 或 `unknown`。`not_observed` 只限这次有足够观察条件但没观察到。不可见、未展开、登录阻塞或缺原文用 `unknown`。硬事实另用 `correct`、`incorrect`、`unverified`、`not_applicable`。没有任何适用硬事实时才用 `not_applicable`，不能用它当正确。

## 最小旁注

保留原始 `answers/<task_id>_提取.json`。在 `observations/<task_id>.json` 用 `templates/检测旁注.json` 写旁注。既有台账不用加列，以下扩展只放新文件。

| 字段 | 最小用途 |
|---|---|
| `schema_version`、`task_id` | 版本和原任务关联，当前旁注版本为 1 |
| `evidence_kind` | `live_capture` 现场、`user_report` 材料转述、`synthetic_test` 程序夹具 |
| `capture_origin` | `consumer_ui` 顾客入口、`provider_api` 后台调用、`offline` 离线 |
| `observed_at`、会话定位 | 带时区时间和 `conversation_url` 或匿名 `session_id`，未知留空 |
| `context` | 入口、模型、联网、思考、记忆、个性化、账号代号、地区、是否独立会话 |
| `coverage` | 五项各自的状态、已采数量、可确认总数 |
| `outcomes` | 六个结果分别记录，不相互推导 |
| `evidence` | 支持结果的文件路径和具体定位 |

重复测量时加 `phase`（before/after 等）、`window`（日期或预注册时间窗）和 `question_type`（brand/non_brand/unknown）。来源正文映射加 `citations`，硬事实核验加 `fact_checks`。这些在需要时填写，不要求把未知记录补成看似完整。

`coverage` 使用 `answer`、`reference_panel`、`landing_urls`、`paragraph_map`、`source_archives`。每项结构如下。分母不明用 null，不能拿链接节点数填总数。

```json
{"state":"partial","captured":3,"expected":5,"note":"面板显示五项，已确认三项"}
```

状态支持 complete、partial、missing、unknown、not_exposed、not_applicable、blocked。数量是独立条目数，重复 DOM 节点只留在原始文件。全文一般填 0/1 或 1/1；也可留数量空、用状态加证据。来源归档的分母是本次明确选定需分析的来源数，不能用所有页面外链。

证据位置示例只说明结构，必须替换为真实文件。

```json
{"path":"answers/task-0001_提取.json","locator":"text 中第二个回答段","sha256":"可选，填该文件的真实 SHA-256"}
```

脚本检查文件是否存在、定位是否已填，以及可选 hash 是否相符。定位的含义和事实支持度由人复核。

`outcomes` 的名称为 `reference_list`、`body_citation`、`brand_mention`、`brand_recommendation`、`brand_citation_support`、`hard_facts`。前三种来源判断限定我方登记作品。品牌推荐需要 `recommendation.quote` 为捕获正文中的原句，`position` 填列表位次或 `unranked`。品牌词与非品牌词分开报告。

硬事实明细示例：

```json
{
  "claim":"回答中的实际硬事实原句",
  "fact_id":"事实库里的实际编号",
  "verdict":"correct",
  "evidence":[{"path":"source_archives/事实库当期快照.md","locator":"对应事实行"}]
}
```

claim 必须逐字取自所选回答正文，不能另写一句已核事实替代回答里的主张。全部相关硬事实逐条核对后才设置 `hard_fact_review_complete: true`。有一句错，整体填 incorrect；未核完填 unverified。

## 旧记录兼容和按题补采

- 原 `url/time/text/links` 仍能读。没有覆盖旁注时默认未知，不补造 `false`。
- `tasks.csv` 旧五列顺序保留，新列 `sample_index` 追加在最后。旧 `round` 始终是题序，不能当重复次数。
- `init_batch.py` 支持 `题号,问题` 或 `question_id,question`。同时提供两组时必须一致。默认不改变旧任务 ID。
- 原问题库、发布台账、题号、作品 ID 与原目录全部保留。现有批次不重新初始化。
- 回原会话补正文、面板或链接时另存带时间的新文件。在旁注加 `capture_file` 指向批次内相对路径，例如 `answers/task-0001_提取_补采1.json`。原始文件和原旁注版本归档，不覆盖。
- 只补引用关系时把 `citations` 写入旁注，映射器在内存合并，绝不改原始提取。指定补采文件不存在就报错，不会退回旧文件冒充补齐。
- `capture_file` 用最完整的正文快照。不同补采面板、来源原文可分别在 `evidence` 引用，不必把它们硬拼成一次抓取。
- 同一会话补采仍是一个样本；重新发题必须有新的 task_id 和会话记录。

映射器旁注的每条 `citations` 至少需要这些字段。以下为结构示范，不能计入效果。

```json
{
  "paragraph_id":"p2",
  "paragraph_text":"选定快照中的真实段落原文",
  "source_url":"https://example.com/replace-with-real-source",
  "source_id":"s1",
  "marker":"[1]",
  "evidence_method":"manual_verified",
  "verified":true,
  "evidence_ref":"images/本次证据.png 的正文与面板对应关系"
}
```

允许方法为 manual_verified 或 dom_explicit_link。段落必须在选定正文里，网址必须有效且有证据定位。`已确认` 只代表关系记录符合条件，仍需核对实际证据；`evidence_kind` 决定它能否参加现场统计。

映射器保留原七列，再追加 task_id、sample_index、引用状态、证据方法、作品 ID 等。旧消费者若不按 `引用状态=已确认` 过滤，就不能直接把新表行数当引用次数。表里仍可能有同来源多个引用，引用次数与引用答案数要分开。映射表还保存 capture_sha256、observation_sha256、capture_file；审查时核对当前输入，过期映射不计数，需重新运行映射器。

URL 身份匹配先对已登记完整 URL，再对有限已知平台路由的完整作品 ID。只忽略 fragment、默认端口和明确追踪参数，业务 query 保留。跳转、短链及移动版关系没有证据时不猜。`canonical_url()` 是本地比较键，不能据此宣称站点设置了 canonical。

## 脚本使用

在示例命令中把 `$GEO` 设置为本技能路径，把 `$PROJECT` 设置为品牌项目路径。示例不会发题或联网。

```bash
python3 "$GEO/scripts/init_batch.py" --questions "$PROJECT/02_策略/问题库.csv" --output "$PROJECT/05_检测/新批次" --platforms DeepSeek --repeats 3
python3 "$GEO/scripts/map_citations.py" "$PROJECT/05_检测/新批次" --brand 品牌全称,已核简称 --own "$PROJECT/04_发布/发布台账.csv" --platform '*'
python3 "$GEO/scripts/evidence_audit.py" "$PROJECT/05_检测/新批次" --output "$PROJECT/05_检测/新批次/audit/审查1"
python3 "$GEO/scripts/verify_publication.py" "$PROJECT/04_发布/核验/某稿/发布核验.json" --output "$PROJECT/04_发布/核验/某稿/核验结果1.json"
```

三个 Python 新增或修改脚本仅用标准库。JS 在用户正常使用的已加载页面运行。自动化工具使用相应授权能力时，仍按其 DOM 访问边界执行，不得另走隐藏接口。

`map_citations.py` 默认输出派生表 `段落引用.csv`，可用 `--output` 改名保存各次结果。映射后再运行 evidence_audit；后者读取默认映射表。审查输出目录必须不存在，防止覆盖旧结果。

`evidence_audit.py` 输出样本分层、五项补采清单、下一步候选和证据审查 JSON。现场主指标须有完整正文、独立会话、消费者入口、已记录联网设置、带时区采样时间和逐层证据。同平台的会话 URL 或会话代号任一重复，相关记录全部排除。普通首页 URL 不能填成会话 URL；没有唯一会话链接时使用可追溯的匿名会话代号。推荐句有我方支持还要求推荐原句位于已经确认的我方引用段。

未知、材料转述、合成夹具和后台 API 不进入现场效果分母。输出的下一步是待人工决定的候选，不能当自动发布任务。脚本无法验证填写者身份或判断截图真假。

`verify_publication.py` 读取人工保存的公开文本快照。逐一对比审定的关键段，并计算文件与段落 hash。它不会访问网址。仅在记录了现场查看时间、环境及证据时标记人工观察到公开可读。遗漏、编辑或格式变化需复核；可匹配关键段也不代表全篇审查完成。

返回码：初始化、映射和证据审查成功为 0，输入错误为 2。发布核验关键段缺失为 1，输入错误为 2。`check_article.py` 保留原用法，已知错误或字数下限不通过为 1。

## 测量口径

按题号、入口、模型、设置、账号代号、地区及时间窗分别列原始分子和分母，不用总体平均掩盖差异。

- 参考列表出现率以参考列表可完整观察的现场回答为分母。
- 正文引用率以正文和段落映射可完整核对的现场回答为分母。
- 提及和推荐率以完整现场回答为分母，缺证据的旁注排除并单列。
- 硬事实正确率以相关硬事实已完整核对的回答为分母，未核实与不适用另列。
- 准确推荐的分母包含已观察到无推荐，以及有推荐且硬事实已核完的回答。后者核实不完整时仍为未知，不能当失败或成功。
- 带我方支持的准确推荐还需推荐句确实对应我方来源，不能用两个分别发生的事件拼出支持关系。

不同指标分母可能不同。必须一起展示计划数、完成数、可比较数、缺项和失败。没有可用分母时比率用 null，并显示暂无可计算结果。

## 小范围实验和首次检出

先冻结原题、页面、变量、采样设置、日程和成功标准。可从两道题、同一平台开始。一次修改一个页面中的一个关键问题，其他渠道暂缓同题铺稿。设置未改锚题只能帮助识别共同波动，不能自动等价随机对照。

发布后先分段核验，再按约定日程复测。小样本重复问答并非完全独立，模型、搜索排序、个性化及同期内容都会影响结果。结果只支持继续或调整试点，不能直接声称因果提升。

首次检出界限由同一入口、同一作品版本、同一指标的最近有效未检出 t0 和首次检出 t1 给出，记录为 (t0, t1]。未知、失败或没有展开面板不能充当 t0。只有公开时间而无有效负观测时，记录上界和未知下界；到观察结束仍没有阳性则记未检出。旧作品修改后观测到引用不一定采用了新版本，需核对新段落才谈修改后的使用。
