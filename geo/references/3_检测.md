# 3 检测

仅在用户授权检测的范围内发题。初始化和离线审查不访问平台。

## 准备与独立采样

- 从项目题库初始化批次。保留题目原话，记录题号、平台及每个样本的 `sample_index`。
- 固定消费者入口、账号代号、可见模型名、联网、思考、记忆、个性化、语言和地区。未知就记未知，设置改变时另分组。
- 不改网络环境来绕过限制。正常使用目标用户可用的入口，记录实际环境。
- 每个样本开独立会话，发一次原题，不加品牌提示，不在同一会话继续追问。重复采样分散到预先约定的时间，按平台正常操作速度执行。
- 只有实际确认新开会话不会中断前一个答案时，才并行等待。`platforms.json` 的该项默认未知。

## 原始采集

1. 回到原会话，确认答案完成。记录会话 URL 或可追溯的独立会话代号。
2. 保存正文，另展开参考面板，按可见界面加载列表。平台未提供面板就标 `not_exposed`。
3. `extract.js` 只保存已加载页面和链接候选。可以用明确的正文/面板节点或人工选择范围；候选数据默认未确认完整。
4. 存入 `answers/<task_id>_提取.json`。字数只能提醒检查，短答案也可能完整，长文本也可能混入导航。
5. 在 `observations/<task_id>.json` 记录人工复核结果，模板见 `检测旁注.json`。不把来源卡片数、链接节点数或正文长度当覆盖率分母。

## 五种覆盖分别记

| 项 | 记录与补采 |
|---|---|
| 正文 | 是否完整；缺失时回原会话补正文 |
| 参考面板 | 已确认独立条目数与面板显示总数；总数不明留空 |
| 落地 URL | 在已登记的独立来源条目中，有多少拿到原始或落地网址 |
| 段落映射 | 在实际可见的正文引用标记中，有多少连到来源；没有显示链接不推断未引用 |
| 来源原文 | 在本轮选定要分析的来源中，有多少保存了对应公开版本 |

原文、重复节点、跳转网址都保留。用于统计的来源需按实证 URL 归并；未知跳转不能猜目标。自有草稿也不等于公开版本，首次深入分析仍核对公开正文。

## 引用与补缺

`map_citations.py` 只确认有明确段落、网址和证据定位的映射。旧版全页外链只算候选，不再按顺序硬配。`evidence_audit.py` 输出各层结果和补采清单。

补采放新文件，按题和缺项执行，注明原任务及采集时间。只读原会话补面板或 URL 不增加独立样本数。若重新发题，必须建新任务，不能冒充原样本。

遇到登录、验证码、频率或访问限制，记下阻塞项和原会话，报告后停止受阻操作。可以继续其他已授权且不受阻的本地工作。

各平台的 DOM 会变化。过去某平台能直接取链接，只可作为操作提示，每次以实际页面为准。
