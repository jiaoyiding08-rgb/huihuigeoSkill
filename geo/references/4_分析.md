# 4 分析

先读原始证据和覆盖缺口，再作内容判断。每条判断保留题号、样本、来源 URL、作品 ID 和段落定位，未知项目留空。

## 逐题检查

1. 分清参考列表出现、正文引用、品牌提及、明确推荐及硬事实正误。
2. 找出同题被选用的竞争来源。比较它解决了什么决策、提供了哪些输入、动作和边界。
3. 对照实际被引的来源段落和公开版本，确认它支持回答的哪句话。相似措辞只算线索，不能替代引用映射。
4. 将下一步写进 `02_策略/补缺任务.csv`。优先补缺失证据及错误事实，再决定修改内容。

## 不同结果对应什么动作

| 已有证据 | 应检查 | 候选行动 |
|---|---|---|
| 只见参考列表，正文使用未知 | 正文标记、面板关系及来源支持度 | 补映射；证据齐后再决定是否改段落 |
| 我方方法被正文引用，答案没提品牌 | 题意是否需要推荐；被选的是哪个方法段；品牌段是否可读且相关 | 保留有效方法。仅在品牌有助于回答时，试补适用对象或一条已核事实，并复测 |
| 推荐品牌且有我方正文引用 | 推荐句与该来源是否对应，关键事实是否被原文支持 | 核对来源版本和硬事实；保留有效段落，避免无必要重写 |
| 品牌被提到但名称或权益写错 | 错误原句、引用来源、事实库及版本冲突 | 修正对应来源或做官网文字说明，无法编辑的外部页建立纠错任务 |
| 完整采样里没有观察到我方来源 | 当期同题信源、覆盖范围、可访问版本和内容缺口 | 形成页面或渠道假设，小范围试点，不推断文章未收录 |

方法被引而品牌未出现有多种解释。品牌段不完整、用户只需方法、来源版本未更新、模型选择波动都可能发生。必须写成待验证假设，不能直接下原因结论。

## 补缺任务必须具体

一条任务包含要补的页面或来源、渠道、段落、目标题号、依据、缺少的信息、读者新增动作、修改类型和验证方式。未取得目标 URL 就写待补，不虚构页面。已有等价稿件优先修改，同题新稿必须通过 `2_问题.md` 的增量检查。

## 写法卡与报告

保留已有写法卡，只增加样本范围、证据定位、反例及待验证状态。平台来源分布写成某日期某题范围内的观察。多篇共有也不等于因果。

报告按题和入口列分子、分母、未知与失败。同时展示非品牌准确推荐和品牌题事实核验；客户报告也保留这些必要分母，可把明细放附件。不要用总体引用次数代替独立答案数，或把一次变化写成效果。
