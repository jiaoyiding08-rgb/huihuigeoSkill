# 官网与渠道试点

## 自有官网

有可维护官网、稳定 URL 和已核事实时，先做一个能直接读正文的文字页。主题选实际错误或信息缺口，例如机构名称、课程对象与不同产品权益的边界。一个小专题连接两三篇有用页面即可。不要先搬迁整站。

| 做法 | 直接作用 | 证据与限制 |
|---|---|---|
| 正常 HTTP 状态、可读正文、允许所需爬虫访问 | 提供可获取的内容 | 人能打开、爬虫访问、被索引分别核验 |
| Sitemap | 告知支持该机制的搜索服务有哪些 URL | 不能保证抓取、收录或推荐 |
| canonical | 给重复网址指定首选版本 | 是信号，搜索服务可另作选择；保留跳转或标签证据 |
| 真实 HTML 内链和专题导航 | 让重要页面可从其他页面发现 | 用途是发现与导航，不能承诺 AI 采纳 |
| 与可见正文一致的结构化数据 | 提供机器可读的页面和实体信息 | 无法保证富结果或中国 AI 平台引用，不能填写正文没有的事实 |

这些措施只在有权限控制的页面上实施。知乎、搜狐、头条、公众号的站点地图、canonical、schema 和爬虫策略通常由平台控制，本技能只能核验其公开页面和可编辑正文。

采用门槛：有人维护事实和版本；有办法读公开正文并保留快照；愿意至少观察四周；明确哪一条错误或缺失要改。技术试点先看页面可读和目标搜索服务可验证的发现，再按同题真实入口观测引用及准确推荐。服务器访问日志要核验爬虫身份，不能把任意 User-Agent 当作官方爬虫。

## 外部纠错

先保存错误原句、URL、日期及正确事实来源。自己能编辑的旧文建立修订任务；第三方页通过正常纠错入口处理。未得到处理回执前保留待解决状态。事实源头纠正可能减少歧义，效果仍需实际答案复测。

## 何时引入发布助手或完整平台

连续两周记录发布、核验和整理工时。只有每周至少十次相似操作、且预计每周节省一小时以上时，才安排一个平台的试点。这是本工具的采用门槛，不是行业定律。

先试领取任务、打开编辑器、复制或填入内容和回填 URL。保留人工发布与公开版本检查。整套平台还需服务器、数据备份、模型额度、运维和升级负责人；缺少这些条件时继续使用文件和现有脚本。

后台 API 搜索或模型分析单独标记 `provider_api`。它们可以帮选来源、发现问题，不能替代顾客使用的 App 或网页问答。
