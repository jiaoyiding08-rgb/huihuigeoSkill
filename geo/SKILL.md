# GEO Loop Pro 1.0

围绕顾客真实问题，记录 AI 在具体入口里找到的来源、正文引用、品牌提及、推荐及事实准确性。按证据决定该补哪一页、哪个渠道或哪一段，再用独立会话复测。单次结果和质检分数都不能证明提升。

## 方法和项目分开

本目录只放通用方法。一个品牌一个项目文件夹，品牌事实、稿件、公开链接、原始采样及样例都放项目内。

## 每次开始

1. 读项目根目录的 `GEO状态.md`、`AGENTS.md`。缺少时从模板建档。
2. 做用户本次指定的事；未指定时按状态文件的下一步。
3. 按下表只读所需参考。扩字段不改旧题号、作品 ID、批次名或台账旧列。
4. 完成后更新状态，写清已观察、推断、缺项及下一步。

| 步 | 工作 | 参考 |
|---|---|---|
| 1 资料 | 品牌硬事实及经营素材 | `references/1_资料.md` |
| 2 问题 | 顾客原话、题库及新经营动作 | `references/2_问题.md` |
| 3 检测 | 原始答案、来源与覆盖缺口 | `references/3_检测.md` |
| 4 分析 | 逐题逐源确定要补的页面、渠道或段落 | `references/4_分析.md` |
| 5 写作和发布 | 写作、稿外证据、人工审稿及公开版本核验 | `references/5_写作.md`、`references/6_发布.md` |
| 按需 | 证据状态、重复采样、旧记录兼容和脚本接口 | `references/7_证据与复测.md` |
| 按需 | 自有官网、外部纠错及发布助手采用门槛 | `references/8_官网与渠道试点.md` |

品类提示在 `references/品类/`。第一次检测作为基线，后续保持原题、入口和设置，复测时间在实验卡预先约定。

## 必须守住

- 品牌价格、时间、地址、对象、人名职务等按已核事实写。未知细节省掉，不编经历、评价和数据。
- 原始记录不覆盖。缺正文、面板、落地网址或映射时只补缺项。没显示链接只记本次未观察到，不能推断未抓取或未使用。
- 候选链接、材料转述和模拟数据不能算现场正文引用。来源在参考列表里，也不能自动算品牌推荐。
- 遇到登录、验证码或限制，记录阻塞并报告，不绕过、不换号。发布前由用户审稿。本次任务没授权发布时只交付稿件和核验计划。

## 项目结构

```
<项目>/
├── AGENTS.md
├── GEO状态.md
├── 01_资料/         事实库.md、素材库/、图库/
├── 02_策略/         问题库.csv、写法卡.md、补缺任务.csv、实验卡.md
├── 03_内容/         <日期>/：稿件、配图、稿外证据.csv、发布说明.md
├── 04_发布/         账号.csv、发布台账.csv、核验/
├── 05_检测/         <日期>_<说明>/：tasks.csv、answers/、observations/、source_archives/
└── 99_归档/
```

旧目录继续使用；新增旁注与核验文件按需创建。原有四个脚本入口保留。脚本仅处理本地资料，浏览器提取器只读已加载页面，均不自动发题或发布。
